# RAG 智能问答系统 — 项目文档

> 两级检索（FAQ 关键词匹配 + RAG 向量检索）的金融智能问答系统。
> 支持意图识别、Reranker 重排序、Prompt 模板管理。

## 六、需要掌握的知识

### 6.1 RAG 核心概念

| 知识点 | 说明 |
|--------|------|
| **RAG 是什么** | Retrieval-Augmented Generation，检索增强生成。先检索相关文档，再把文档作为上下文喂给 LLM 生成回答 |
| **为什么需要 RAG** | LLM 的知识有截止日期，且可能产生幻觉。RAG 通过外挂知识库解决"知识更新"和"事实准确"问题 |
| **Embedding** | 把文本映射到高维向量空间，语义相似的文本向量距离近 |
| **向量检索** | 基于向量相似度（IP/Cosine/L2）找最相似的文档 |
| **父子分块** | 小块做检索（精准），大块喂 LLM（完整），兼顾准确率和召回率 |
| **Reranker** | 对粗排结果做精排，用更强的模型重新打分，提高最终回答质量 |

## 七、面试高频问题

### Q1：什么是 RAG？为什么需要它？

**答：** RAG（Retrieval-Augmented Generation）是检索增强生成。在 LLM 生成回答前，先从外部知识库中检索相关文档，把文档作为上下文喂给 LLM。原因：
1. LLM 知识有截止日期，RAG 可以接入最新知识
2. LLM 会"幻觉"（编造事实），RAG 通过外部知识约束输出
3. 不需要微调模型就能更新知识，成本低

### Q2：父子分块（Parent-Child Chunking）是什么？为什么这么做？

**答：** 是一种"小块检索 + 大块喂给 LLM"的策略。
- 子块（~300字）：小粒度，用于向量检索，匹配精度高
- 父块（~1200字）：大粒度，是子块所在的完整上下文段落
- 检索时用子块匹配 → 找到对应父块 → 把父块喂给 LLM
- 好处：检索精度高 + 上下文完整，兼顾准确率和召回率

### Q3：为什么需要 Reranker？直接用向量检索的结果不行吗？

**答：** 向量检索是"粗排"，速度快但精度有限。Reranker 是"精排"，用更强的 Cross-Encoder 模型对候选结果重新打分。两步走的好处：
- 第一阶段（粗排）：向量检索，速度快，召回 Top-K（如 10 条）
- 第二阶段（精排）：Reranker 重排序，精度高，选出 Top-N（如 3 条）
- 兼顾了速度和精度

### Q4：Embedding 模型和 Chat 模型的区别？

**答：**
- Embedding 模型（如 BGE-M3）：输入文本，输出固定维度的向量，用于文本相似度计算
- Chat 模型（如 GPT-4、通义千问）：输入对话，输出自然语言文本，用于对话生成
- 在 RAG 中：Embedding 模型负责"检索"，Chat 模型负责"生成"

### Q5：为什么用 Milvus 而不是 Faiss？

**答：**
- Faiss 是本地库，数据存内存，重启就没了，不支持分布式
- Milvus 是服务端数据库，数据持久化，支持分布式部署，适合生产环境
- Milvus 支持标量过滤 + 向量检索的混合查询，功能更丰富

### Q6：什么是向量相似度？IP、Cosine、L2 的区别？

**答：**
- **IP（内积）**：值越大越相似。要求向量已做 L2 归一化，此时等价于余弦相似度
- **Cosine（余弦相似度）**：值域 [-1, 1]，只关心方向不关心长度，值越大越相似
- **L2（欧几里得距离）**：值越小越相似。注意排序逻辑与 IP/Cosine 相反
- BGE 系列模型推荐使用 IP + normalize_embeddings=True

### Q7：为什么需要意图识别？直接走 RAG 不行吗？

**答：**
- 节省算力：闲聊（"你好"）不需要检索，直接回复即可
- 节省 Token：不需要把无关上下文喂给 LLM
- 提升体验：闲聊回复更快，专业问题回复更准
- 安全控制：识别投诉/敏感问题，转人工处理

### Q8：Prompt 模板的作用是什么？

**答：** 将业务逻辑和模型调用解耦。模板定义了"怎么问"，LLM 负责"怎么答"。好的模板可以显著提升回答质量。RAG 系统中 Prompt 模板是影响最终效果的三大因素之一（另外两个是检索质量和模型能力）。

### Q9：如何处理多轮对话？

**答：** 把对话历史存入 messages 列表，每次请求时带上历史消息：
```python
messages = [
    {"role": "system", "content": "系统指令"},
    {"role": "user", "content": "第一轮问题"},
    {"role": "assistant", "content": "第一轮回答"},
    {"role": "user", "content": "第二轮问题（当前）"},
]
```

### Q10：如何评估 RAG 系统的效果？

**答：**
- **检索评估**：召回率（Recall）、精确率（Precision）、MRR（平均倒数排名）
- **生成评估**：答案准确性（是否基于检索到的文档）、答案完整性、幻觉率
- **用户体验**：响应时间、回答相关性、用户满意度
- 常用工具：RAGAS 框架，自动评估 RAG 系统的检索和生成质量

### Q11：依赖注入是什么？为什么在项目中使用？

**答：** 依赖注入（DI）是把一个类依赖的对象从外部传入，而不是在内部创建。
```python
# 不好的写法（耦合）
class MilvusVectorStore:
    def __init__(self):
        self.embedder = EmbeddingService()  # 硬编码，无法替换

# 好的写法（依赖注入）
class MilvusVectorStore:
    def __init__(self, embedding_service):
        self.embedder = embedding_service  # 从外部注入，可替换
```
好处：解耦、可测试（Mock 注入）、可替换（换模型/换数据库只改注入参数）
